# 工具讲义 · VS Code 调试器（1 小时）

**日期**：2026-09-07　**配套**：`lesson04_energy.py`
**为什么是今天**：你 6 天踩了 50+ 个 bug，**全部**靠 `print` 定位。这一小时是目前投入产出比最高的一件事，剩下 13 周天天回本。

`print` 有三个致命缺点，你已经全撞过：

1. **每想看一个新变量，就要改一次代码、重跑一次。** lesson04 跑一次 8 秒，改十次就是 80 秒外加十次手滑机会。
2. **`print` 本身会引入 bug。** 9/4 的 bug 11（`%6.f` vs `%.6f`）、bug 13（assert 消息没占位符）、9/5 的整个 D 类 5 个 bug —— **全在打印上，一个都不在物理上。**
3. **`print` 只能看你事先想到要看的量。** 而 bug 恰恰藏在你没想到的地方。

调试器把这件事整个翻过来：**程序停住的那一刻，所有变量都在那儿**，你想看哪个看哪个，不改代码、不重跑。

## 1. 断点 + 变量面板（10 分钟）

行号左边点一下 → 红点 → F5 跑到那儿停住。停住之后左侧四个面板：**变量 / 监视 / 调用堆栈 / 断点**。

**变量面板就是那一刻的完整现场**，`Locals` 里是全部局部变量 —— 不用一个个 `print`。

| 键 | 名字 | 意思 |
|---|---|---|
| **F5** | 继续 | 跑到下一个断点 |
| **F10** | 单步跳过 | 执行这一行，**函数调用当作一步** |
| **F11** | 单步进入 | 执行这一行，**是函数调用就进去** |
| **Shift+F11** | 单步跳出 | 把当前函数跑完，回到调用它的地方 |
| **Ctrl+Shift+F5** | 重启 | |
| **Shift+F5** | 停止 | |

**练习 A（3 分钟）**：在 `65` 行 `al=alpha(A)` 设断点 → F5 → 看 `A` → 按 **F11** 进 `alpha()`，看参数 `A` → **Shift+F11** 出来 → 看 `al`。

## 2. 调试控制台（10 分钟）—— 今天最值钱的一个

下方面板的「**调试控制台 / DEBUG CONSOLE**」。程序停住时，可以在这里敲**任意 Python 表达式**，用的就是当前现场的变量。

停在 `76` 行时依次敲：

```
al
Ex2(al)
Ex2(0.0)
L/xi
(L + Ex2(al)/2/xi)/xi
```

**你可以直接调用自己写的函数、直接把公式敲进去算。** 不改代码，不重跑。

> 🔴 9/5 那个错了的 ±5% 容差，如果当时在调试控制台里敲一下 `Ex2(0.0)`，**五秒钟**就知道它返回的是 0 还是 2。
> 这一条单独就抵得上今天这一小时。

⚠️ 纪律：调试控制台里**能改变量**（敲 `n_se = 999` 真的会改），但那会污染现场，之后所有判断都不可信。**只用来看，不用来改。**

## 3. 条件断点（10 分钟）—— 蒙卡的救命功能

`for i in range(N)` 跑 100 万次。普通断点在这里等于死刑：按 F5 一百万次。

**右键行号 → 添加条件断点**，三种：

| 类型 | 填什么 | 用在哪 |
|---|---|---|
| **表达式** | `i == 999999`　`A == 1.0`　`r_new < 0`　`math.isnan(x)` | **只在出问题的那一次停** |
| **命中次数** | `>5000` | 前 5000 次不停 |
| **记录消息（Logpoint）** | `i={i} r={r_new}` | **不停，只打印** = 一个不用改代码的 print，而且**不会留在源码里被你忘掉** |

**练习 B（3 分钟）**：在 `101` 行 `counts[j]+=1` 设条件断点，条件写 `j == M-1`，看它第一次命中时 `t` 和 `r_new` 各是多少。

> 顺便你就亲眼看见 9/4 bug 19 的「夹边界」到底在夹什么了。

> **表达式断点是「用判据找现场」的工具。** 你写 assert 是在问「什么样的 bug 会让它失败」；
> 条件断点是把同一句话反过来用：**「什么条件下我要看现场」**。同一种思维，两个出口。

---

## 4. 异常断点（10 分钟）—— assert 炸的那一刻停住

断点面板顶部有两个勾：`Raised Exceptions` / `Uncaught Exceptions`。勾上之后，**异常抛出的那一瞬间程序停住，局部变量全都还在**。

| | traceback | 异常断点 |
|---|---|---|
| 你看到什么 | 行号 + 你自己写的那句消息 | 那一行的**全部变量**，还能在调试控制台里接着算 |
| 想多看一个量 | 加 print，**重跑** | 直接看，不重跑 |
| 现场还在吗 | 没了 | **还在** |

> 9/2 立的规矩「**一条 assert 要有两个独立算出来的量**」，配上异常断点才完整：
> **assert 告诉你哪两个量对不上；异常断点让你当场看见这两个量分别是多少、以及它们各自是从哪一步来的。**

## 5. 调用堆栈（5 分钟）

「调用堆栈」= 谁调用了谁。**点任意一层，变量面板跟着切到那一层的现场。**

`scatter()` 里的 `assert A**2+2*A*mu_cm+1>0` 炸了，你点上一层就能看见：是哪个 `A`、第几次调用、当时 `E` 是多少。

> 9/1 学的「读 traceback 三条规则」在这里变成点鼠标 —— 而且**每一层的变量都还活着**。

---

## 6. 一条纪律：调试器慢，先判断要不要缩规模

调试器下每一行都要经过 debugpy，比直接跑慢一个量级以上。

**开跑前先问一句：这个 bug 是统计性的，还是确定性的？**

- **确定性**（公式错、下标错、初始化位置错、名字覆盖）→ **把 N 砍到最小**，秒级复现。
- **统计性**（3σ 偶尔炸、只在 N 大时出现、灾难性相消）→ 规模不能砍，改用**条件断点 / logpoint**。

今天的练习是确定性的，所以第一步就是砍 N。

# 练习：用调试器重抓一个你已经知道答案的 bug（30 分钟）

## 步骤

0. `cp lesson04_energy.py dbg_practice.py`，**在副本上做**，别动原文件。（git 明天才建，今天先用复制。）
1. 副本里把规模砍小：`N=20000`、`N_hist=2000`、`N_hist_B=1000`。
   （我实测过这三个数：**其余八条验证全部通过，只有目标那一条炸**，0.1 秒跑完。）
2. 把 `Ex2` 的 `alpha==0` 分支从 `return 2` 改回 **`return 0`** —— 这就是那个 bug。
3. **先直接跑一次**（不调试），记下：炸在第几行、消息是什么。

  File "E:\BNCT_GPU\my_code\energy1.py", line 185, in <module>
    assert abs(n_mean - Renew) < 3*n_se,\
AssertionError: n_mean有偏差偏大，Renew=18.197537

4. 勾上 `Raised Exceptions`，F5 重跑，停在炸的那一刻。在变量面板里找出这四个数：
   **`n_mean` / `Renew` / `Naive` / `n_se`**

5. 在调试控制台敲 `al`、`Ex2(al)`，确认走的是哪个分支。
6. 在 `Ex2` 内部设**条件断点**，条件 `alpha == 0`，重跑，F10 走一步，看返回值。
7. 改回 `return 2`，重跑，确认那一条恢复到 ±1σ 量级。
8. 副本删掉，或留着明天一起 commit 进 git。

## 一个必须记住的观察（这才是练习的重点）

这个 bug **只被一条验证抓住**：

| 验证 | 用到 `Ex2` 吗 | 结果 |
|---|---|---|
| `4b over`（普适界，**工程档**） | **没有** | ✅ 照常通过（0.995 稳稳落在 [2/3, 1] 带内） |
| `4b' renew`（更新理论，**3σ 档**） | **用了** | 💥 +7.47σ |

> **同一个 bug，工程档判据完全看不见，3σ 档当场炸。**
> 这不是「工程判据没用」——它抓的是别的东西（模型误差）。
> 这是 9/2 那个问题的又一个实例：**每条验证覆盖了哪几行代码？剩下哪几行还没人管？**
> `Ex2` 这个函数，在 4b' 写出来之前是**零覆盖**的 —— 它可以返回任何数而不被发现。
